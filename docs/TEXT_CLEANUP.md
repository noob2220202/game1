2026-11-27 · **웹과 앱 모두** · 1편 · 2편 반영(커밋 전) · 3편은 2026-11-28에 §6 목록대로 반영(커밋 전, §6.1에 최종 결과).
판정 원본: `work/qa/cleanup/decisions_ep12.json` · `decisions_ep3.json` · `judge_notes.json`(gitignore — 작업 폴더에만). 앱 빌드에서만 다른 것과 포장 절차는 `docs/APP_RELEASE.md`. 2편 정본 문자열의 변경 기록은 `docs/DESIGN_EP2.md` §12.11에 있고, 1편은 `docs/DESIGN.md`의 해당 절에 날짜 메모를 달았다.

## 1. 규칙 (의뢰인 원문)

> "동그라미 친 저런거 추후에 어플 출시할때는 깔끔하게 없어야해"
> "저거뿐만아니라 쓸데없는 문구들. 다 없애야해. 저런거 ai특유의 주석같은거"
> "웹도같이 1편도 작업 해"

첫 말은 2편 크레딧 작은 글씨에 동그라미를 치고 한 말이다: `만든 사람 너의 친구 · 하루에게` · `목소리: AI 음성 · 사진: AI 생성 + 직접 편집` · `소리: 전부 직접 합성` · `플레이 1분 · 힌트 0회` · `이 게임은 아무 데이터도 보내지 않았어요. 카메라도, 마이크도 쓰지 않았어요.`

- **범위**: 웹과 앱, 1편과 2편. 1편 수정은 이번 정리에 한해 승인됐다. 3편은 2026-11-28에 같이 반영했다(§6 · §6.1 · §6.2).
- **없앨 것**: 극 밖에서 플레이어에게 말을 거는, AI가 단 주석 같은 쓸데없는 문구. 다음이 여기에 든다.
  - 제작 정보
  - 플레이 시간과 통계
  - '이 게임은 …'으로 시작하는 말
  - 개인정보 안심 문구
  - '~할 수 있어요' 같은 안내
  - 괄호 덧말
  - '권장', '자동 저장' 같은 시스템 설명
- **'깔끔하게'**: 글자만 숨기지 말고 노드를 지운다. 빈자리, 남은 `·`, 빈 머리글, 어긋난 배치가 하나도 없어야 한다. 데이터 문자열만 비우면 렌더러의 대체 문자열(fallback)이 같은 글을 다시 그리므로 대체 문자열도 지운다.

## 2. 적용 규칙 (리드 결정 O1–O12)

판정을 따르되, 아래 규칙이 판정보다 앞선다. 판정이 규칙이나 공정성·플레이와 부딪히면 규칙을 따르고, 그렇게 한 곳을 기록한다.

| # | 규칙 |
|---|---|
| O1 | 크레딧은 웹과 앱 모두 **제목만** 남긴다. 1편은 `ecr-title`, 2편은 제목 블록이고, 모두 정중앙의 같은 배치다. 대체 문자열도 지운다. |
| O2 | 앱에는 안 나오는 웹 전용 문제 해결 문구는 남긴다: `<noscript>`, 카카오톡·인앱 브라우저 카드, `404.html`. 클라이맥스의 `(PC: 마우스 또는 Space)`는 웹에만 둔다(G.APP이면 숨김 — 1편도 2편과 같은 G.APP 규칙). |
| O3 | 극 안 문구는 `※`가 붙거나 설명조여도 남긴다. 극 안 앱의 줄을 지우기 전에는 DESIGN에서 찾아본다. 단서, 증거 경로, 퍼즐 문구, 공정성 사실이면 **남기고 기록한다**. 폰 설정이 '이 게임'을 말하면 메타이므로 지운다(줄이 어색해지면 실제 폰 말투로 고친다). |
| O4 | 플레이에 필요한 안내는 남긴다. 이어폰 테스트의 안내는 짧은 한 줄까지이고, 이어폰 권유는 편마다 이어폰 테스트 화면에 하나만 둔다. 타이틀 바닥의 플레이 시간, '어두운 곳에서', '권장', '자동 저장'은 지운다. |
| O5 | 콘텐츠 안내는 화면과 버튼을 남기고 글은 한 줄로 줄인다. 1편 `공포 연출과 스토킹·실종 소재가 있습니다.`, 2편 `공포 연출과 스토킹·감금 소재가 있습니다.` 1편에만 힌트 위치 한 줄 `📓 힌트는 오른쪽 위 수첩에 있어요.`를 둔다(2편은 하드모드라 없다). |
| O6 | AI 음성 고지(OpenAI TTS 정책상 필요)는 크레딧에서 뺀다. 대신 편마다 극 밖 설정/⏸ 메뉴에 **한 줄** `목소리는 AI 음성입니다.`를 둔다. 화면의 다른 곳에는 없다. |
| O7 | 2편 점검 카드에는 도움말 `스토킹·디지털 성범죄 피해: 112 · 여성긴급전화 1366`과 [계속]만 남긴다. 보안 점검 줄은 지운다. |
| O8 | 1편 공유 문구와 주소는 그대로 두고, 토스트만 `복사했어요.`로 바꾼다. |
| O9 | '이번 선택 남기기'를 누른 뒤 화면에 다른 변화가 없으면 `바꿨어요.`만 보인다. 변화가 있으면(버튼이 사라지면) 상태 줄을 지운다. |
| O10 | data-qa 값은 바꾸지 않는다. 지운 글자를 기다리던 드라이버는 data-qa를 기다리게 고친다. |
| O11 | 2편 ⏸의 `개인정보 ›`: 토글 `내가 보낸 말 다시 보이기`만 남기고, 머리글의 개인정보 틀과 설명 줄을 지운다. 토글은 중립 자리에 둔다. |
| O12 | 코드 주석, `beats.js`의 `note:`, `assets/img/meta.json`의 `_qa`는 화면에 안 나온다. 소스는 그대로 두고, 앱 포장 단계에서 빼거나 지운다(APP_RELEASE.md '포장'). |

## 7. 새 문구를 쓸 때 (재발 방지)

- [ ] 극 밖 글자가 '이 게임은 …'이나 '이 이야기는 …'으로 시작하지 않는다.
- [ ] 다음 문구가 하나도 없다: 제작 정보, 플레이 시간과 통계, '권장', '자동 저장', 개인정보·권한 안심 문구, 플레이 환경 안내(밝기, 어두운 곳).
- [ ] 다음 문구가 하나도 없다: '~할 수 있어요' 안내, 괄호 덧말(`(TTS)` `(방향 표시)` `(이어폰 추천)` `(270°)`), 시스템을 설명하는 둘째 문장.
- [ ] AI 음성 고지는 편마다 설정/⏸ 한 줄뿐이다.
- [ ] 극 안 문구는 실제 폰·앱 말투로 쓴다. 단서나 공정성 사실이면 설명조라도 남긴다.
- [ ] 문구를 지울 때 대체 문자열, 빈 노드, 남은 `·`, 빈 머리글이 남지 않는다.
- [ ] data-qa는 그대로이고, 드라이버는 글자 대신 data-qa를 기다린다.
